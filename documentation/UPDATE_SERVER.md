# Сервер обновлений

Цель: APK ставится **один раз**, а дальше каждый `git push` превращается в обновление, которое игроки получают при следующем запуске игры.

## Как это устроено

```
git push ─► GitHub Actions (publish-updates.yml)
              ├─ проверка скриптов + все тесты + сквозной тест обновления кода
              ├─ экспорт кода игры в .pck (≈0,4 МБ) ─► пакет game.core, подпись релизным ключом
              ├─ пакеты из content_src/ (только новые версии)
              ├─ APK — только если изменилась его версия (config/version / config/apk_build)
              ├─ состояние сервера ─► ветка update-server (история публикаций, 5 последних версий)
              └─ GitHub Pages ─► https://maillunex-lang.github.io/lastufa/
                                   catalog.json, catalog-beta.json, packages/…, apk/…, index.html

Телефон: запуск ─► загрузочный экран проверяет catalog.json ─► «Доступно обновление игры» ─►
         загрузка (докачка, проверка SHA-256 и подписи) ─► перезапуск ─►
         Bootstrap подключает game.core.pck ДО загрузки остальных скриптов ─► новая версия
```

- **Bootstrap** (`core/bootstrap.gd`) — первая автозагрузка. Подключает `.pck` только если: подпись сделана релизным ключом (ключи `dev_*` для кода не принимаются никогда), SHA-256 совпадает, пакет собран под ту же версию движка и сборку APK (`min_apk_build`) и новее кода внутри APK.
- **Защита от «кирпича»**: если игра с новым кодом дважды не дошла до главного меню, версия отключается, а пакет автоматически откатывается на предыдущую рабочую версию. Если её нет, запускается код из APK.
- Номер версии кода: `<major>.<minor>` из `project.godot` + номер запуска CI (например, `0.1.27`). APK всегда `x.y.0`.

## Что обновляется без APK, а что требует нового APK

| Без APK (через сервер) | Нужен новый APK |
|---|---|
| Любые GDScript-скрипты, включая автозагрузки | Новая **автозагрузка** (список в project.godot) |
| Новые классы (`class_name`), сцены, UI | Нативные библиотеки / GDExtension |
| Данные ядра (`data/core`), баланс, локации | Новая версия Godot |
| Пакеты контента, моды, регионы | Разрешения и настройки Android-манифеста |
| | Изменение `Bootstrap` или доверенных ключей |

Когда нужен новый APK: увеличьте `config/apk_build` (и при необходимости `config/version`) в `project.godot`. CI соберёт APK и положит его на страницу сервера; старые пакеты кода с меньшим `min_apk_build` новый APK примет, а пакеты для нового APK старые установки не примут — им будет предложено обновить APK.

## Первоначальная настройка (один раз)

1. **Сделать репозиторий публичным**: Settings → General → Danger Zone → Change visibility → Public.
   - В репозитории лежит `tools/keys/dev_private.pem` — это ключ разработки. Код им подписать нельзя (Bootstrap его не принимает), а в release-сборках он не доверяется вообще.
2. **Включить Pages**: Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. **Добавить секреты**: Settings → Secrets and variables → Actions → New repository secret:
   - `AF_SIGNING_KEY` — содержимое `release_signing_private.pem` (целиком, с строками BEGIN/END);
   - `AF_ANDROID_KEYSTORE_B64` — содержимое `keystore_b64.txt`;
   - `AF_ANDROID_KEYSTORE_PASS` — содержимое `keystore_pass.txt`.
   Эти файлы никогда не коммитьте. Храните копию в надёжном месте: без ключа подписи обновления не примутся уже установленными играми, а без keystore новые APK нельзя будет поставить поверх старых.
4. Запустить workflow: Actions → **Publish updates** → Run workflow (или любой push).
5. Открыть `https://maillunex-lang.github.io/lastufa/` — там статус сервера и ссылка на APK.
6. На телефоне: удалить старую debug-версию (другая подпись), поставить релизный APK.

## Повседневная работа

- Изменили код → `git push` → через ~10 минут игроки увидят «Доступно обновление игры».
- Бета-канал: Actions → Publish updates → Run workflow → channel `beta`. В игре: настройка `content/channel = beta` (UI выбора канала — в планах).
- Откат публикации (локально, с клоном ветки `update-server` в `dist/`):
  ```bash
  git worktree add dist update-server
  python3 tools/afpkg.py status --out dist
  python3 tools/afpkg.py rollback game.core --out dist          # на предыдущую версию
  python3 tools/afpkg.py rollback game.core --to 0.1.12 --out dist
  cd dist && git commit -am rollback && git push origin update-server
  ```
  После пуша ветки перезапустите workflow или задеплойте Pages. Игроки с более новой версией её сохранят (откат меняет то, что предлагается к установке), у игрока всегда есть кнопка «Откатить» в «Контент и моды».
- Свой сервер вместо Pages: любая статика с поддержкой HTTP Range (nginx, S3/R2, CDN) — скопируйте содержимое ветки `update-server` и добавьте URL в `config/update_servers.json` (зеркала перебираются по порядку). Для разработки: `python3 tools/afpkg.py serve --out dist`.

## Проверено

- `tools/test_code_update.sh` — на настоящей экспортированной сборке: обновление автозагрузки и новый `class_name` работают после подключения пакета; подменённый `.pck` отвергается; битое обновление отключается после двух неудачных стартов с автоматическим откатом; игра сама находит, качает, ставит и после перезапуска запускает новый код с HTTP-сервера.
- Не проверено на Android-устройстве (тот же код, но реальный запуск на телефоне ещё не делался).
