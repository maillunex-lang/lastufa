# Доставка контента и обновления

## Что в APK, что в пакетах

| В APK | В пакетах (user://content/packages) |
|---|---|
| Движок Godot, нативные библиотеки (godot-sqlite) | Регионы и локации, модели, текстуры, звуки |
| Все скрипты (GDScript скомпилирован) | Предметы, заражённые, таблицы лута, погода, правила-скрипты |
| Ядро `data/core` (стартовый регион, базовые данные) | Задания, локализации, моды, DLC |
| UI, загрузчик, менеджеры | (в будущем) подписанные системные `.pck` |

Обновление APK требуется только при изменении кода, нативных библиотек или версии API модов. Пакеты хранятся в `user://` и переживают обновление APK.

## Типы пакетов

`ENGINE`, `SYSTEM`, `REGION`, `ASSET`, `AUDIO`, `QUEST`, `LOCALIZATION`, `MOD`, `DLC`. У каждого — своя версия, зависимости и требования совместимости.

## Манифест (`manifest.json`, для модов допустим `mod.json`)

```json
{
  "id": "region.sterlitamak",
  "name": "Регион: Стерлитамак",
  "type": "REGION",
  "version": "1.1.0",
  "min_game_version": "0.1.0",
  "api_version": 1,
  "systems": {"locations": "^1.0.0", "zombies": "^1.0.0"},
  "dependencies": {"core": ">=0.1.0"},
  "conflicts": [],
  "size": 4357,
  "data_format": 1,
  "author": "Ashenfall Team",
  "released": "2026-10-31",
  "changelog": "…",
  "description": "…",
  "files": [{"path": "data/location.json", "sha256": "…", "size": 1234}],
  "signature": "base64(RSA-SHA256)",
  "key_id": "dev_private"
}
```

- `id`: `[a-z0-9][a-z0-9_.-]{2,63}`, `core` зарезервирован.
- Ограничения версий: `*`, `1.2.3`, `>=`, `>`, `<=`, `<`, `^` (тот же major), `~` (тот же minor), несколько через пробел/запятую.
- `systems`: совместимость с версиями игровых систем (`content`, `rules`, `world_map`, `survival`, `locations`, `zombies`, `items`).
- **Подпись** покрывает детерминированную строку: `ashenfall-package-v1`, id, версия, тип, min_game_version, отсортированные зависимости и отсортированные пары `path sha256`. Так как хеши всех файлов подписаны, подпись защищает и содержимое. Реализации: `AfManifest.signing_payload()` и `tools/afpkg.py:signing_payload()`.
- Доверенные ключи: `config/trusted_keys/*.pem`. Ключи `dev_*` принимаются **только в debug-сборках**.

## Правила безопасности при установке

1. Пути: только относительные, без `..`, `\`, `:`, только каталоги `data/ assets/ scripts/ locale/` и разрешённые корневые файлы; белый список расширений.
2. Исполняемые файлы (`.gd .gdc .cs .so .dll .dex .jar .apk .exe .sh .py .js .wasm…`) запрещены всегда.
3. `.pck` разрешён только в `SYSTEM`/`ENGINE`-пакетах с действительной подписью.
4. Каждый файл архива должен быть в манифесте и совпадать по размеру и SHA-256; лишние файлы — отказ (защита от подмены и zip-bomb по размеру).
5. Пакет с подписью, которая не проверяется, отклоняется. Неподписанные моды ставятся с предупреждением.
6. Атомарность: распаковка в `staging/` → проверка → текущая версия переименовывается в `backups/<id>/<время>_<версия>` → staging переименовывается в `packages/<id>` → транзакция в БД. Ошибка на любом шаге возвращает прежнюю версию. Хранятся 2 резервные копии на пакет.
7. Незавершённые staging-каталоги удаляются при запуске.

## Сервер и зеркала

Раскладка (создаётся `tools/afpkg.py build`):

```
catalog.json
packages/<id>/<version>/manifest.json
packages/<id>/<version>/files/<path>
packages/<id>/<version>/<id>-<version>.zip
```

Подойдёт любой статический хостинг/CDN с поддержкой HTTP Range. Список зеркал: `config/update_servers.json` (по каналам) или «Настройки → Сервер обновлений» (через запятую). Зеркала перебираются по порядку; после ошибки загрузка переходит на следующее зеркало. Откат публикации — удалить версию из `packages/<id>/` и перегенерировать каталог (`afpkg.py catalog`); клиенты увидят предыдущую версию как актуальную.

> Сейчас в конфиге только локальные адреса разработки (`127.0.0.1`, `10.0.2.2` для эмулятора). Продакшн-CDN не развёрнут.

## Алгоритм обновления

1. `check_updates()` — `catalog.json` с первого живого зеркала; состояния: `available`, `update`, `installed`, `incompatible`.
2. `enqueue(entry)` — загрузка манифеста новой версии, валидация, **дифф по SHA-256** с установленными файлами (из `package_files`). В очередь попадают только изменившиеся/новые файлы. Проверка свободного места (загрузка + сборка).
3. Очередь в `system.db` (`download_jobs`, `downloads`) — переживает перезапуск игры и устройства. Каждый файл качается в `*.part` с `Range: bytes=N-` (206 — дописываем, 200 — заново). Параллельность — настройка (по умолчанию 2). Повторы с экспоненциальной задержкой (до 6 попыток), смена зеркала при сбое.
4. Готовый файл проверяется по SHA-256; несовпадение — удаление и повтор.
5. Когда все файлы задания готовы — staging собирается из скачанных файлов и неизменённых локальных, затем обычная атомарная установка (с подписью и бэкапом) и перезагрузка реестра.
6. UI: очередь, прогресс, скорость, ETA, пауза/возобновление/отмена, приоритет, «приостановить всё», причина блокировки (например, «ожидание Wi-Fi»).

Бинарные дельты внутри файла (bsdiff и т.п.) **не реализованы** — дифф пофайловый. Для больших ассетов это значит: меняйте ассеты отдельными файлами.

## Ручной импорт ZIP

«Контент и моды → Импорт ZIP»: системный выбор файла (`FileDialog` с нативным диалогом) или папка импорта `user://import` (путь показан в UI). Поддерживается архив, где манифест лежит в корне или в единственной папке.

## Управление объёмом

«Контент и моды → Хранилище»: размеры пакетов, бэкапов, недокачанных файлов, кэша, сохранений и свободное место; очистка кэша и бэкапов; список регионов; «только Wi-Fi». Удаление пакета — во вкладке «Установленные» (запрещено, если от него зависят другие).

## Совместимость сохранений

Сохранение хранит список активных пакетов. Если пакета нет — загрузка продолжается, пользователь получает предупреждение, предметы помечаются недоступными, состояния районов и заражённых неизвестных типов сохраняются как есть и возвращаются после переустановки пакета (покрыто тестом `test_saves::test_missing_package_content_preserved`).
